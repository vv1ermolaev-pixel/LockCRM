# LockCRM

Личная CRM для контактов людей, которых знаю лично.

## Как запустить

### Что нужно установить

- Node.js (LTS) и pnpm
- Docker Desktop
- OpenSpec - для работы над фичами: `npm install -g @fission-ai/openspec@latest`. Требования лежат в `openspec/`, команды `/opsx:*` - в Claude Code

### База данных (PostgreSQL в Docker)

1. Если файла `.env` ещё нет — скопируйте `.env.example` в `.env` и заполните значения (имя пользователя, пароль, название базы, порт `5432`, строку подключения `DATABASE_URL`).
2. Запустите Docker Desktop.
3. В папке проекта выполните:

   ```
   docker compose up -d
   ```

4. Проверить, что база работает:

   ```
   docker compose ps
   ```

   В колонке `STATUS` должно быть `healthy`.

Остановить базу: `docker compose stop`. Данные при этом сохраняются.

### Первый запуск приложения

Один раз, в папке проекта:

```
pnpm install
pnpm db:migrate
```

`pnpm db:migrate` создаёт в базе таблицы. Повторный запуск безопасен: уже применённые изменения он пропускает.

Тестовые данные (1000 вымышленных контактов с заметками, у трети задана частота общения — поэтому на главной сразу виден блок «Пора связаться»), по желанию:

```
pnpm db:seed
```

Скрипт работает только с пустой базой. Если контакты уже есть, он ничего не меняет и ничего не удаляет.

### Запуск приложения

```
pnpm build
pnpm start
```

Откройте в браузере: http://localhost:3000

Приложение доступно только с этого компьютера: входа по паролю нет, поэтому с других устройств в сети оно не открывается.

Остановить: нажмите `Ctrl + C` в окне, где запущено приложение, или закройте это окно.

Режим для разработки (изменения в коде видны сразу, но работает медленнее): `pnpm dev`.

## Как проверить, что всё работает

### Руками

1. Откройте http://localhost:3000 — видно список всех контактов и их количество.
2. Нажмите «Добавить контакт», впишите имя и нажмите «Добавить» — контакт появится в списке с пометкой «Новый».
3. Начните вводить его имя в строке поиска — в списке останется он один. Откройте его карточку.
4. Впишите заметку и нажмите «Добавить заметку». Обновите страницу (F5) — заметка на месте.
5. Вернитесь к списку. Поиск ищет везде: по имени, «Кто это», «Откуда знакомы», телефону, почте и заметкам. Слова запроса могут найтись в разных полях.
   - Впишите слово из только что добавленной заметки — контакт найдётся, под именем видна строка «Заметка: …» с выделенным словом.
   - На тестовых данных: «8 974 639 74 31» находит Григория Степанова по телефону (номер записан как «+7 974 639-74-31»), «Новосибирск Баранов» — Виктора Баранова по «Откуда знакомы».
   - Сузьте окно до ширины телефона и поищите по телефону или почте — под именем появится строка «Телефон: …» или «Почта: …».
6. Откройте тот же адрес в другом браузере — там те же контакты и та же заметка.
7. В карточке контакта нажмите «Удалить». В окне видно имя и сколько заметок удалится вместе с ним. «Отмена» — ничего не меняется. «Удалить» — открывается список, контакта в нём больше нет.
8. Напоминания «Пора связаться»:
   - В окне «Новый контакт» или «Изменить» выберите в поле «Как часто общаться», например, «Раз в неделю». В карточке под полем видно «Следующий раз — до …». Срок считается от последней заметки или нажатия «Связались», а если их не было — от дня, когда контакт добавлен.
   - На главной над поиском есть блок «Пора связаться» с теми, у кого срок уже прошёл, самые просроченные сверху. Если таких нет, блока нет. Пока в поиске есть запрос, блок скрыт.
   - Нажмите галочку у контакта: строка меняется на «Отметили общение» с кнопкой «Отменить» и через 5 секунд исчезает. «Отменить» возвращает строку, как была. Карточка при этом не открывается и заметка не появляется.
   - В карточке то же делает кнопка «Связались» (она есть, если задана частота): срок сдвигается, внизу на 5 секунд появляется «Отметили общение» с «Отменить». Новая заметка тоже сдвигает срок и убирает контакт из блока.

### Автоматически

Пока приложение запущено, выполните:

```
pnpm test:e2e
```

Тесты проходят весь сценарий выше в Microsoft Edge и Google Chrome. Каждый тест работает только со своим контактом и в конце его удаляет — остальные контакты не трогает.

Тесты идут на приложении, которое открыто по адресу http://localhost:3000, и сами ничего не пересобирают. После изменений в коде остановите приложение и запустите его заново (`pnpm build`, затем `pnpm start`), иначе тесты проверят старую версию.

## Выкатка на сервер

Прототип работает на https://app.funkicrm.ru (сервер `157.22.207.202`, вход: `ssh crm`).

На сервере входа по паролю нет: любой, кто знает адрес, видит и меняет контакты. Поэтому там только тестовые данные — настоящие контакты туда не вносите.

### Как выкатить новую версию

Отправьте коммит в ветку `main` (`git push`). Дальше всё произойдёт само (`.github/workflows/deploy.yml`):

1. GitHub Actions собирает Docker-образ приложения и кладёт его в GHCR (хранилище образов GitHub). Тег образа — SHA коммита.
2. Копирует папку `deploy/` на сервер в `/srv/lockcrm/deploy` и запускает `deploy.sh`.
3. `deploy.sh` на сервере: скачивает образ → разовый контейнер из того же образа применяет миграции → запускается новая версия → проверка `/health` (smoke) → удаляются старые образы, кроме текущего и предыдущего.

Если миграции упали, новая версия не запускается и продолжает работать старая. Если smoke красный, выкатка считается упавшей, и GitHub присылает письмо. Автоматического отката нет.

### Как проверить

- Ход выкатки: вкладка **Actions** в репозитории на GitHub (или `gh run watch` в терминале).
- https://app.funkicrm.ru/health отвечает `{"status":"ok","version":"<SHA коммита>"}`. Версия совпадает с последним коммитом в `main` — значит, на сервере новая версия.

### Откат (только вручную)

```
ssh crm
bash /srv/lockcrm/deploy/rollback.sh
```

Запускает предыдущую версию приложения. Миграции базы при этом не откатываются.

### Что где лежит на сервере

| Что | Где |
| --- | --- |
| Пароли базы | `/srv/lockcrm/.env` (права 600, в git не попадает) |
| Скрипты выкатки | `/srv/lockcrm/deploy/` (копируются из репозитория при каждой выкатке) |
| История выкаток | `/srv/lockcrm/releases.log` (последняя строка — текущая версия) |
| Контейнеры | docker compose, проект `prod`: `db` (PostgreSQL), `app`, разовый `migrate` |

Посмотреть контейнеры: `docker ps`. Логи приложения: `docker logs prod-app-1`.

Тестовые данные на сервере (работает только с пустой базой, ничего не удаляет): `bash /srv/lockcrm/deploy/seed.sh`.

### Первая настройка сервера (уже сделана, нужна только для нового сервера)

1. `deploy/setup-server.sh` с sudo: даёт пользователю `crmapp` доступ к Docker, создаёт `/srv/lockcrm` и направляет nginx для `app.funkicrm.ru` в приложение.
2. Создать `/srv/lockcrm/.env` с правами 600: `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `DATABASE_URL=postgresql://USER:PASSWORD@db:5432/DB`.
3. В GitHub (Settings → Secrets and variables → Actions): секрет `DEPLOY_SSH_KEY` (приватный ключ деплоя; публичный — в `~/.ssh/authorized_keys` на сервере), переменные `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS`.

| Команда | Что делает |
| --- | --- |
| `pnpm db:studio` | Открывает просмотр базы в браузере |
