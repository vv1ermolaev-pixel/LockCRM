# Design

## Context

Зачем фича — см. `proposal.md`, требования — `specs/contact-groups/spec.md` и `specs/keep-in-touch/spec.md`. Здесь — как сделать в текущем коде.

Что есть сейчас:

- Таблицы `contacts` и `notes` (`src/db/schema.ts`), миграции `0000`, `0001`. Заметки удаляются вместе с контактом (`on delete cascade`).
- Главная (`src/app/page.tsx`) — серверная страница: в `Promise.all` читает `listContacts(query)`, `countContacts()` и `listDueContacts()`. Сверху вниз: заголовок, блок «Пора связаться» (`DueContacts`), поиск, список. Общий список — клиентский `ContactList`, сервер шлёт ему только данные строк. Строки — `li#contact-<id>`, на это опираются e2e-тесты.
- Поиск (`contact-search.tsx`) пишет запрос в адрес как `/?q=…` и **заменяет весь адрес**: любой другой параметр пропадёт.
- «Добавить контакт» после сохранения ведёт на `/?added=<id>` — весь список с подсветкой нового.
- Кнопка «Все контакты» на карточке — ссылка на `/`.
- Форма контакта одна на «Новый» и «Изменить» (`contact-form-dialog.tsx`), данные читает `readContactForm` и проверяет `contactSchema` (zod). Ошибки — по полям.
- Сравнение без регистра и «ё» уже есть: `normalizeText` в `src/lib/search.ts` и SQL `replace(lower(…), 'ё', 'е')` в `contacts.ts`.
- `src/lib/*` с базой помечены `server-only`, `db` берёт `DATABASE_URL` из окружения. Действия в `src/app/actions.ts` вызывают `revalidatePath` из `next/cache`.
- Тестов, кроме e2e на Playwright, нет; e2e работают на локальной базе с живыми данными. Vitest в стеке CLAUDE.md, но не установлен.
- Цвета — только токены в `src/app/tokens.css`; цветов под метки групп там нет.
- Библиотеки перетаскивания в проекте нет.

## Goals / Non-Goals

**Goals:**

- Группы и участие в них — обычные таблицы с внешними ключами: удаление группы или контакта само убирает связи.
- Один порядок групп, хранимый на сервере, во всех местах, где группы перечисляются.
- Фильтр по группе — параметр адреса, его читает серверная страница; поиск и фильтр не затирают друг друга.
- Тесты проверяют поведение из спеки так, как его увидит пользователь, и не ломаются от переписывания внутренностей.
- Существующие e2e-тесты остаются зелёными без правок.

**Non-Goals:**

- Тесты интерфейса в Vitest (нужны jsdom и testing-library — новые библиотеки). Экранные сценарии проверяются руками сейчас и e2e на Playwright позже.
- CI — отдельной работой.
- Возврат на главную с прежним **поисковым запросом** из карточки — сейчас он тоже теряется, фича это не меняет; сохраняется только группа.
- Перестановка групп в окне «Группы» — только в ряду фильтра (решение пользователя).

## Decisions

### 1. Две таблицы и перечень цветов

```
groups          id (identity), name text not null, color group_color not null,
                position integer not null, created_at
contact_groups  contact_id → contacts.id on delete cascade,
                group_id   → groups.id   on delete cascade,
                primary key (contact_id, group_id), index (group_id)
```

- Уникальность названия — индекс `unique (replace(lower(name), 'ё', 'е'))`, то же правило, что в поиске. Код проверяет дубль сам, чтобы показать ошибку у поля, а индекс — защита от гонки; нарушение индекса (код `23505`) превращается в ту же ошибку «Такая группа уже есть».
- `group_color` — `pgEnum` с ключами палитры (решение 2). Цвет обязателен: у группы без цвета метку нечем рисовать.
- `position` — место группы в пользовательском порядке; все списки групп сортируются `position, id`. Новая группа — `max(position) + 1`. Удаление дыр не чинит: порядок остальных от дыры не меняется, а следующая перестановка всё равно перепишет позиции подряд (решение 4).
- Удаление группы — `delete from groups`, связи уходят каскадом, контакты не трогаются. Удаление контакта так же убирает его связи — число людей в группе уменьшается без отдельного кода.

Альтернативы:

- массив `group_ids` в `contacts` — нет внешних ключей, удаление группы пришлось бы вычищать вручную во всех контактах;
- группы как свободные теги-строки без своей таблицы — негде хранить цвет и порядок, переименование — правка всех контактов;
- порядок как массив id в отдельной строке настроек — второй источник правды, который надо держать в согласии с таблицей групп при создании и удалении.

### 2. Палитра — общий модуль и токены

`src/lib/group-colors.ts` без `server-only` (его используют схема, браузер и сервер, как `contact-frequency.ts`):

- ключи по порядку палитры: `green, yellow, peach, pink, lilac, blue, teal, gray`;
- русские названия для диктора и подсказок: «Зелёный», «Жёлтый», «Персиковый», «Розовый», «Сиреневый», «Голубой», «Бирюзовый», «Серый»;
- `groupColorClasses` — полные строки классов (`"bg-group-pink"` …), чтобы Tailwind их увидел при сборке;
- выбор цвета новой группы — цвет, который реже всего встречается, при равенстве — первый по порядку палитры.

В `tokens.css` — 8 токенов `--color-group-<key>`, светлые пастельные, текст на всех — `ink` (контраст с ним выше 4.5:1 у любого светлого фона; проверить при подборе). Отправная точка: green `#d4ecc2`, yellow `#f3e3a0`, peach `#f8d9bf`, pink `#f6d0d8`, lilac `#e2d6f3`, blue `#cfe1f5`, teal `#c6e9e2`, gray `#e3e5df`. Зелёный не совпадает с `pistachio` (подсветка заголовков), жёлтый — с `butter` (пометка просрочки и нового контакта), чтобы метка не читалась как статус.

### 3. Готовые группы — отдельной миграцией

- `pnpm db:generate` → `drizzle/0002_*.sql`: тип, две таблицы, индексы.
- `pnpm exec drizzle-kit generate --custom --name=default_groups` → пустой `drizzle/0003_default_groups.sql`, в него — `insert into groups (name, color, position) values ('Семья','pink',1), ('Друзья','green',2), ('Знакомые','yellow',3), ('Коллеги','blue',4) on conflict do nothing`.

Отдельный файл, а не правка сгенерированного: следующая генерация не спутает данные со схемой, а мигратор применит оба файла по порядку разовым контейнером, как сейчас. Пользователь потом может удалить готовые группы — миграция второй раз не запускается, они не вернутся.

### 4. Модуль `src/lib/groups.ts` (`server-only`)

Чтение:

- `listGroups()` — `id, name, color, contactCount` в порядке `position, id`; нужен главной (фильтр, окно, метки), карточке и окну контакта;
- `getContactGroupIds(contactId)`.

Запись — функции принимают `db` или транзакцию, чтобы ими пользовались и действия окна «Группы», и сохранение контакта:

- `createGroup(name)`, `renameGroup(id, name)` — проверка названия (решение 6), у новой — цвет по правилу палитры и позиция в конце; результат `{ ok: true, id } | { ok: false, error }`;
- `setGroupColor(id, color)`, `deleteGroup(id)`;
- `reorderGroups(orderedIds)` — в транзакции переписывает `position` подряд по присланному списку. Id групп, которых уже нет, отбрасываются; группы, которых нет в списке (созданы в другой вкладке), остаются после присланных в своём прежнем порядке. Так устаревший список из старой вкладки ничего не теряет и не падает;
- `setContactGroups(tx, contactId, { groupIds, newNames })` — создаёт новые группы (если название уже есть без учёта регистра и «ё» — берёт существующую), затем заменяет связи контакта: удалить все, вставить выбранные. Идентификаторы групп, которых уже нет (удалили в другой вкладке), отбрасываются вставкой через `select … from groups where id in (…)` — не ошибка.

Почему не в `contacts.ts`: тот и так большой и про поиск; группы — отдельная возможность со своей спекой.

### 5. Действия в `src/app/actions.ts`

- `createContact`, `updateContact` — запись контакта и `setContactGroups` в одной транзакции: упала запись групп — контакт не сохранён, ошибка у поля.
- `createGroup(formData)`, `renameGroup(id, formData)`, `setGroupColor(id, color)`, `deleteGroup(id)`, `reorderGroups(orderedIds)` — тонкие обёртки над `groups.ts` с проверкой входа и `revalidatePath("/", "layout")`. После `revalidatePath` сервер перерисовывает открытую страницу, и окно «Группы», фильтр и метки получают новые данные без перезагрузки.

### 6. Правила названия и данные формы — `src/lib/validation.ts`

- `groupNameSchema`: `trim`, не пусто («Укажите название»), до 40 символов («Слишком длинно — до 40 символов»).
- `groupNameKey(name)` = `normalizeText(name.trim())` — тот же ключ, что у индекса; им же клиент находит «друзья» → «Друзья» до отправки.
- `contactSchema` получает `groupIds: number[]` и `newGroups: string[]` (каждое — `groupNameSchema`); `readContactForm` читает их через `formData.getAll`. Ошибка нового названия возвращается полем `newGroups` и показывается под «Группами».

### 7. Поле «Группы» в окне контакта

В `contact-form-dialog.tsx` новый `GroupsField` — после «Как часто общаться», на всю ширину:

- все группы в пользовательском порядке метками-переключателями (`button` с `aria-pressed`, цвет группы; отмеченная — с галочкой и обводкой `ink`); для каждой отмеченной — скрытый `input name="groupIds"`;
- под ними — поле «Новая группа» и кнопка «+» (Enter тоже добавляет): если ключ совпал с существующей — она отмечается, иначе в конце появляется отмеченная метка новой группы (без цвета до сохранения, настоящий выдаст сервер) и скрытый `input name="newGroups"`; крестик на ней убирает;
- группы приходят в `ContactFormDialog` пропом `groups` от `AddContactButton` и `EditContactButton`; текущие группы контакта — в `defaultValues.groupIds`.

Альтернатива — выпадающий список с поиском (combobox): удобнее при сотнях групп, но это новый компонент и хуже на телефоне; у личной CRM групп — единицы и десятки.

### 8. Фильтр — параметр `group` в адресе, место — над блоком

- Порядок на главной сверху вниз: заголовок, `GroupFilter`, `DueContacts`, поиск, список. Фильтр выше блока, потому что он управляет и блоком.
- Главная читает `?group=<id>`. Группа ищется в `listGroups()` (он грузится всё равно); нет такой — фильтра нет, выделено «Все».
- `listContacts(query, groupId)`, `countContacts(groupId)` и `listDueContacts(groupId)` получают необязательный `groupId` и добавляют условие `contacts.id in (select contact_id from contact_groups where group_id = …)`. Один способ фильтрации для списка, счётчика и блока — они не разойдутся.
- Клиентский `GroupFilter`: «Все», кнопки групп в пользовательском порядке (точка цвета + название), выбранная — фон `ink`, текст белый, `aria-current`; в конце — кнопка «Группы» (решение 10). Кнопки групп — ссылки (`Link`, `replace`, `scroll={false}`), адрес строится из текущих параметров: `group` ставится или убирается, `q` сохраняется, `added` убирается. На телефоне ряд прокручивается вбок, не переносится. Перетаскивание — решение 9.
- `ContactSearch` строит адрес тоже из текущих параметров: меняет только `q`, `group` оставляет.
- Ссылки на карточку из списка и из блока «Пора связаться» несут группу: `/contacts/<id>?group=<id>`; карточка строит «Все контакты» как `/?group=<id>`. «Назад» в браузере работает и так — фильтр в адресе.
- Тексты: подзаголовок «В группе «Теннис» — 3 контакта»; при поиске — «Найдено: 1 из 5» (из людей группы); пустая группа и пустой поиск в группе — `EmptyState` с текстами из спеки.
- «Добавить контакт» по-прежнему ведёт на `/?added=<id>` — фильтр снимается, новый контакт виден в общем списке (спека).

Альтернатива — фильтр в состоянии клиента без адреса: теряется при обновлении и «Назад», а серверу всё равно нужен параметр, чтобы отфильтровать блок и счётчик.

### 9. Перестановка в фильтре — dnd-kit

Библиотека (согласована с пользователем): `@dnd-kit/core` 6.3.1, `@dnd-kit/sortable` 10.0.0, `@dnd-kit/utilities` 3.2.2 — последние стабильные; peer — `react >= 16.8`, React 19 подходит. При установке ещё раз проверить, что версии последние.

- В `GroupFilter` — `DndContext` и `SortableContext` с `horizontalListSortingStrategy` только вокруг кнопок групп: «Все» и «Группы» вне его, поэтому всегда первое и последнее.
- Датчики:
  - `PointerSensor` с порогом сдвига 8 px — короткий клик мышью остаётся переходом по ссылке;
  - `TouchSensor` с задержкой 300 мс и допуском 8 px — на телефоне быстрый свайп листает ряд, а зажатие берёт группу;
  - `KeyboardSensor` с `sortableKeyboardCoordinates` — Пробел берёт, стрелки двигают, Пробел кладёт, Escape отменяет.
- Тексты для диктора — свои русские `accessibility.announcements` и `screenReaderInstructions` («Группа «Теннис» взята. Стрелками влево и вправо — переместить, Пробел — положить, Escape — отменить», «… перемещена на место 2 из 5», «… положена», «Перемещение отменено»).
- Порядок обновляется в состоянии клиента сразу при отпускании (`arrayMove`) и уходит в `reorderGroups`. Ошибка — состояние возвращается к прежнему, `toast.error("Не удалось сохранить порядок групп")`. После успешного ответа сервер присылает тот же порядок, и состояние синхронизируется с пропом.
- Ссылка-кнопка после перетаскивания не должна срабатывать как клик: в `onDragEnd` ставится флаг, и ближайший `click` по ссылке отменяется (`preventDefault`). Выбранный фильтр поэтому не меняется (сценарий «Фильтр остаётся»).
- Во время перетаскивания кнопка приподнята (`shadow-card`) и слегка прозрачна на старом месте; при «уменьшить движение» — без анимации перестановки.

Альтернативы:

- `@dnd-kit/react` — новое поколение той же библиотеки, но версия 0.x, не стабильная;
- нативное HTML-перетаскивание — не работает пальцем на телефоне и с клавиатуры;
- своё перетаскивание на событиях указателя — много кода ради доступности и телефона, которые библиотека уже решает;
- стрелки ↑↓ в окне «Группы» — проще, но пользователь выбрал перетаскивание прямо в фильтре.

### 10. Метки групп в списке и на карточке

- `GroupBadge` — `Badge` с классом цвета группы и текстом `ink`; используется в списке, на карточке, в фильтре и в окне «Группы».
- В `ContactListItem` добавляется `groupIds: number[]` — подзапросом `array_agg(group_id)` в `listContacts` (через построитель запросов, как `bestNoteBody`, из-за той же особенности Drizzle с именами колонок). Названия, цвета и порядок клиент берёт из списка групп, который страница передаёт один раз, и выстраивает метки в этом порядке. Так переименование, смена цвета и перестановка не требуют пересчёта строк, а данных по сети меньше.
- В строке метки идут под «Кто это» (и под строкой «почему найден» при поиске), с переносом. Строка по-прежнему одна ссылка `li#contact-<id>`.
- Карточка: `Detail` «Группы» на всю ширину после «Откуда знакомы»; данные — `getContactGroupIds` + `listGroups` в общем `Promise.all`.

### 11. Окно «Группы»

Клиентский `GroupsDialog` на существующем `Dialog`, открывается кнопкой «Группы» (иконка `TagsIcon`) в конце ряда фильтра. Группы — пропом с сервера в пользовательском порядке, после каждого действия приходят свежие (решение 5).

Строка группы: кнопка-метка цвета → под строкой раскрывается ряд из 8 кружков палитры (`aria-label` — название цвета, выбранный отмечен); название и «12 человек» (`pluralize` с формами «человек/человека/человек»); кнопки «Переименовать» и «Удалить» (иконки 44×44 с `aria-label`).

- Переименование — название превращается в поле с «Сохранить» и «Отмена» (Enter / Escape), ошибка — под полем.
- Удаление — строка превращается в подтверждение прямо в окне: «Удалить группу «Теннис»? 3 человека останутся в контактах, просто без этой группы» и кнопки «Отмена» / «Удалить». Не второе модальное окно поверх первого: на телефоне это теснее и путает фокус.
- Внизу — поле «Новая группа» и «Добавить», ошибка — под полем; новая группа появляется последней строкой.
- Ошибка сети — `toast.error` в стиле остальных форм.

Палитра раскрывается в строке, а не в `Popover`: компонента `popover` в проекте нет, а раскрытие в строке проще и на телефоне удобнее.

### 12. Тесты — поведение из спеки, а не повтор реализации

Правила:

- **Один тест — один сценарий спеки.** `describe` — требование, `it` — сценарий, по-английски, смысл — как в спеке (например, `it("rejects a name that differs only in case: «теннис» when «Теннис» exists")`). По списку тестов видно, какие сценарии покрыты.
- **Тест действует, как экран.** Шаги WHEN — вызов тех же действий из `actions.ts`, что вызывают формы и кнопки, с `FormData`, собранной так же, как её отправляет форма (`createContact`, `updateContact`, `deleteContact`, `createGroup`, `renameGroup`, `setGroupColor`, `deleteGroup`, `reorderGroups`).
- **Проверка — то, что увидит пользователь.** THEN читается теми же функциями, которыми страницы строят экран: `listGroups` (порядок, названия, цвета, число людей), `listContacts`, `countContacts`, `listDueContacts`, `getContactGroupIds`, — и текстом ошибки, который действие вернёт форме.
- **Ожидаемое — буквально из спеки**: «Такая группа уже есть», `peach` для первой новой группы после выкатки, порядок «Семья, Друзья, Знакомые, Коллеги». Тест не вычисляет ожидаемое той же функцией или формулой, что и код.
- **Внутренности не тестируются отдельно**: выбор цвета, ключ названия, устройство SQL, вызовы внутренних функций. Они проверяются через поведение; переписать их, сохранив поведение, можно без правки тестов.
- **Экранные сценарии** (клик против перетаскивания, свайп на телефоне, клавиатура и диктор, место фильтра на странице, адрес страницы) в Vitest не проверяются: руками сейчас, e2e на Playwright позже. В задачах для каждого сценария указано, где он проверяется.

Устройство:

- Ставится последняя стабильная `vitest` (проверить при установке; на момент плана — 5.0.x) как dev-зависимость, скрипт `"test": "vitest run"`.
- **Отдельная тестовая база** в том же Postgres из Docker: адрес — `DATABASE_URL` с приставкой `_test` к имени базы; `.env` не меняется. `globalSetup` создаёт базу, если её нет. Перед каждым тестом база пересоздаётся (`drop schema public, drizzle cascade`) и получает все миграции — состояние ровно «сразу после выкатки», включая готовые группы. Поэтому сценарии про цвет новой группы и порядок детерминированы и не зависят от ваших данных.
- **Защита данных**: если имя тестовой базы не оканчивается на `_test` или совпадает с базой из `DATABASE_URL`, тесты останавливаются до первого запроса.
- `vitest.config.ts`: окружение `node`, тесты `src/**/*.test.ts`, алиас `@` → `src`, `server-only` → пустой модуль (в Next он пустой для серверного кода), `next/cache` → модуль с пустым `revalidatePath` (служебная часть Next без логики, вне Next она не работает), `fileParallelism: false` — тесты по очереди, база одна.
- Порядок по TDD: написать тесты сценариев → `pnpm test`, увидеть красный по правильной причине → код → зелёный.

## Risks / Trade-offs

- [`lower()` для кириллицы зависит от локали базы] → образ Postgres по умолчанию в `en_US.utf8`, поиск «Петр» → «Пётр» на этом уже работает; тест сценария «Такая группа уже есть» («Теннис» / «теннис») это подтвердит.
- [Пересоздание тестовой базы перед каждым тестом медленнее] → миграции — несколько файлов, это доли секунды на тест; при десятках тестов — секунды. Если станет долго — пересоздавать раз на файл и чистить таблицы.
- [dnd-kit 6.x/10.x не обновлялся с конца 2024] → используется малая и устоявшаяся часть API; при поломке на новой версии React — переход на `@dnd-kit/react`, когда он станет стабильным.
- [После перетаскивания браузер засчитает клик и переключит фильтр] → флаг после `onDragEnd` гасит ближайший клик (решение 9); проверяется руками сценарием «Фильтр остаётся».
- [На телефоне зажатие для перетаскивания можно спутать с прокруткой ряда] → задержка 300 мс и допуск 8 px: быстрый свайп листает, зажатие берёт; проверяется руками на настоящем телефоне или в эмуляции касаний.
- [Две вкладки переставляют группы одновременно] → `reorderGroups` принимает устаревший список без потерь (решение 4), побеждает последняя перестановка; пользователь один, принимаем.
- [Ряд фильтра длинный при многих группах] → прокрутка вбок на телефоне, перенос на компьютере; у личной CRM групп немного.
- [Метки делают строку списка выше] → метки переносятся только когда не влезают; у контакта без групп высота прежняя.
- [Окно контакта открыто, а группу в это время удалили в другой вкладке] → её отметка при сохранении молча отбрасывается (решение 4); пользователь один, принимаем.
- [После «Удалить» группу не вернуть] → подтверждение называет число людей, контакты не теряются.

## Migration Plan

1. `pnpm db:generate` → `drizzle/0002_*.sql`: `CREATE TYPE "group_color"`, `CREATE TABLE "groups"` (с `position`), `CREATE TABLE "contact_groups"`, внешние ключи, индексы. Существующие таблицы не меняются.
2. `drizzle-kit generate --custom --name=default_groups` → `drizzle/0003_default_groups.sql` с четырьмя группами и их позициями.
3. Выкатка обычная: миграции разовым контейнером, затем новый образ, smoke `/health`.
4. Ручной откат на прошлый образ безопасен: старый код новые таблицы не читает. Таблицы и группы остаются в базе и при повторной выкатке не мешают (миграции уже отмечены применёнными).
