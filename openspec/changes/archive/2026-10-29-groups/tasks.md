# Tasks

Как писать тесты — design, решение 12. Коротко: один тест — один сценарий спеки; тест вызывает те же действия, что экран, и проверяет то, что увидит пользователь; ожидаемое — буквально из спеки; внутренние функции отдельно не тестируются. Каждая задача с кодом — по TDD: тесты названных сценариев → `pnpm test`, красный по правильной причине → код → зелёный. Сценарии, помеченные «руками», — экранные: проверяются вручную на `pnpm dev`, e2e на Playwright — позже.
