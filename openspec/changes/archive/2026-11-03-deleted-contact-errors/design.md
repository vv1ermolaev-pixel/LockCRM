# Design

## Context

Причины изменения — в proposal.md, раздел «Why». Что сейчас происходит в коде:

- `addNote` вставляет заметку, не проверяя контакт. Внешний ключ `notes.contact_id` отвергает вставку (код Postgres 23503), действие бросает ошибку, Next.js пишет её в лог, клиент показывает общее сообщение.
- `updateContact` бросает `Error("Contact … not found")`, если `update … returning` ничего не вернул.
- `markContacted` для контакта, которого нет, возвращает `{ ok: true, previous: null }` и вызывает `revalidatePath`. Клиент показывает «Отметили общение», а перерисованная карточка становится «не найдено».
- Ошибки, которые действие бросило, в production-сборке приходят на клиент без текста: Next.js скрывает сообщение серверной ошибки. Поэтому различить «контакт удалён» и «сбой» клиент может только по возвращённому значению, а не по брошенной ошибке.
- Текст «…Проверьте, что база данных запущена…» записан строкой в 11 местах семи компонентов.
- `src/test/db-errors.test.ts` получает ошибку базы как раз через заметку к удалённому контакту.

## Goals / Non-Goals

**Goals:**
- «Контакт удалён» — обычный ответ действия, не исключение: без записи в лог и без перерисовки страницы.
- Тексты сообщений в одном месте, чтобы новые действия брали их оттуда, а не писали свои.

**Non-Goals:**
- Различать «нет интернета» и «сервер недоступен» (решение владельца: один текст).
- Следить за удалением контакта в другой вкладке без нажатия кнопки.
- Менять схему базы.

## Decisions

### 1. «Контакт удалён» — возвращаемое значение действия

`addNote`, `updateContact` и `markContacted` возвращают `{ ok: false, contactDeleted: true }`, если контакта нет. Тип общий, `ContactDeleted` в `src/app/actions.ts`. Он входит в `NoteActionResult`, `ContactActionResult` и `MarkContactedResult`.

- `addNote`: в транзакции сначала `select … for update` строки контакта, как уже делает `markContacted`. Нет строки — ответ «удалён», вставки нет. Блокировка не даёт удалить контакт между проверкой и вставкой: удаление в другой вкладке подождёт конца транзакции.
- `updateContact`: вместо `throw` транзакция возвращает `null`, действие отвечает «удалён». `update` сам блокирует строку, поэтому группы пишутся только существующему контакту.
- `markContacted`: строки нет — ответ «удалён».

В ответе «удалён» `revalidatePath` не вызывается. Перерисовка заменила бы карточку на «не найдено», а вместе с ней пропали бы набранный текст и открытое окно. Это противоречит спеке. Список на главной и так читает базу при каждом открытии, по тому же принципу, что в `deleteContact`.

Альтернативы:
- Ловить ошибку внешнего ключа 23503. Подходит только для заметки: у `update` и `markContacted` такой ошибки нет. Кроме того, ошибка базы остаётся способом управлять поведением, а не сбоем.
- Бросать особую ошибку и распознавать её на клиенте. Не работает в production-сборке: Next.js скрывает текст серверных ошибок.

### 2. Тексты в `src/lib/action-messages.ts`

```ts
export const CONTACT_DELETED = "Этот контакт уже удалён";
export const BACK_TO_LIST = "К списку контактов";
export function failureMessage(what: string) // → `Не удалось ${what}. Попробуйте ещё раз.`
```

Компоненты зовут `failureMessage("сохранить заметку")` и так далее. Строки «Проверьте, что база данных запущена» в коде не остаётся. Константа `NETWORK_ERROR` в `groups-dialog.tsx` уходит.

Альтернатива: поправить хвост строки в каждом из 11 мест. Через месяц новое действие снова скопирует старый текст.

### 3. Где показывается «Этот контакт уже удалён»

- Форма заметки и окно «Изменить» — общий компонент `ContactDeletedNotice` (`src/components/contact-deleted-notice.tsx`): текст и `Link` «К списку контактов». В форме заметки он стоит под полем вместо строки ошибки, в окне — над кнопками. У него `role="alert"`, чтобы экранный диктор прочитал его сразу. Поля не сбрасываются: формы неуправляемые, а сброс есть только в ветке успеха.
- «Связались» на карточке — `toast` (нейтральный, не красный) с `action: { label: BACK_TO_LIST, onClick: () => router.push(listHref) }`, без «Отменить».
- «Связались» в блоке — новое состояние строки `{ kind: "deleted" }` в `due-contacts.tsx`. Строка выглядит как подтверждение: текст «Этот контакт уже удалён», имя, полоса обратного отсчёта, без «Отменить». Через `UNDO_WINDOW_MS` она уходит тем же `leave(id)`, что и после обычной отметки.

Адрес ссылки (`listHref`) — тот же `backHref`, который карточка `src/app/contacts/[id]/page.tsx` уже считает для «Все контакты». Карточка передаёт его в `NoteForm`, `EditContactButton` (дальше в `ContactFormDialog`) и `MarkContactedButton`. Окно «Новый контакт» ответа «удалён» не получает, поэтому для него prop необязательный.

### 4. Тест логов переходит на другую ошибку

Сценарий «текст заметки не попадает в лог» сохраняется. Ошибку теперь вызывает временное ограничение `alter table notes add constraint reject_every_note check (false)`, так же как соседний тест делает с `contacts`. Postgres кладёт строку целиком в detail ошибки 23514, поэтому тест проверяет то же самое: значений в логе нет, код и имя ограничения есть.

### 5. Тесты: только Vitest, экран проверяется руками

Решение владельца: правка небольшая и не трогает основной путь, поэтому новых e2e нет. Тестами Vitest закрывается всё, что проверяется без браузера:

- сервер: `addNote`, `updateContact` и `markContacted` к удалённому контакту возвращают «удалён» и ничего не пишут в базу;
- сервер не обновляет страницы при ответе «удалён». В тесте `next/cache` подменяется через `vi.mock`, проверяется, что `revalidatePath` не вызывался. Это главный риск правки: перерисовка заменила бы карточку на «не найдено», и набранный текст пропал бы;
- тексты сообщений из `src/lib/action-messages.ts`;
- текст заметки не попадает в лог (решение 4).

Сценарии экрана из спек — сообщение под полем, окно не закрылось, ссылка, сообщение внизу экрана, строка блока, тексты при сбое — проверяются руками по списку шагов в задаче приёмки. Удаление — во второй вкладке, сбой — DevTools → Network → Offline.

Альтернативы:
- e2e на Playwright для каждого сценария (22 теста). Отклонено владельцем: e2e — только для основного пути и крупных фич.
- Тесты компонентов через Testing Library и jsdom. Требуют двух новых библиотек, а действия сервера в них были бы заглушками.

Существующие e2e не меняются. Ни один из них не проверяет старый текст «Проверьте, что база данных запущена».

## Risks / Trade-offs

- [Поведение экрана не закрыто автотестами: поломку в компоненте поймает только ручная проверка] → Компоненты меняются в одну ветку `if`, а главный риск (перерисовка страницы) закрыт тестом на сервере. Перед PR проходится список ручных шагов, после выкатки — сценарий в двух вкладках на сервере.
- [`select … for update` в `addNote` — лишний запрос на каждую заметку] → Один запрос по первичному ключу. Для личной CRM разницы не видно.
- [Строка «удалён» в блоке выглядит почти как «Отметили общение»] → Отличается текстом и отсутствием «Отменить». Если владелец захочет другой вид, это правка только `due-contacts.tsx`.
- [После «Этот контакт уже удалён» карточка остаётся на экране, и можно нажать ещё раз] → Каждое повторное нажатие честно отвечает тем же сообщением. Данных это не портит.

## Migration Plan

База и миграции не меняются. Выкатка обычная: merge → образ → миграции (пустые) → новый образ → smoke `/health`. Откат — предыдущий образ, данные совместимы в обе стороны.
