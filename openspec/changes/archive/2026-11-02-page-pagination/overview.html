Показать ещё

Главная больше не выводит все контакты разом. Сначала видно 20, остальные — по кнопке «Показать ещё». Число показанных хранится в адресе страницы, а только что добавленный контакт стоит первой строкой.

1Коротко

  • Общий список на главной показывает по 20 контактов по алфавиту. Под списком — «Показать ещё»: добавляет следующие 20.
  • Так же работают результаты поиска и список выбранной группы.
  • Блок «Пора связаться» не делится на части: в нём по-прежнему все, кому пора.
  • Статус: спроектирована. Требования, план и задачи готовы, код ещё не писали. Отмечено задач: 0 из 7. Автотесты (программы, которые сами проходят сценарий и сверяют результат) запланированы на все 31 сценарий: часть проверяет данные напрямую, часть проходит сценарий в настоящем браузере.

3Как это работает

Части по 20, по алфавиту

Сначала видно первые 20. Каждое нажатие «Показать ещё» добавляет следующие 20 в конец. Порядок прежний: весь список и группа — по алфавиту; поиск — сначала те, у кого все слова запроса в имени, потом остальные по алфавиту.

Контактов 45: сначала 20 → нажали → 40 → нажали → 45, кнопки больше нет.
Подзаголовок считает всех

Число под «Контакты» не зависит от того, сколько строк видно.

Видно 20 строк, а под заголовком «145 контактов». В группе — «В группе «Теннис» — 52 контакта». При поиске — «Найдено: 37 из 145».
Новый список — снова первые 20

Выбрали или сняли группу, начали, поменяли или очистили поиск — показываются первые 20 нового списка.

Открыто 60 контактов, нажали «Теннис» → первые 20 людей из «Теннис».
Сколько показано — в адресе

В адресе страницы появляется ?page=3 — «открыто три части, то есть 60 строк». Поэтому обновление страницы, «Назад» из карточки, «Все контакты» и ссылка в другом браузере показывают столько же. Нажатия «Показать ещё» не добавляют шагов в историю: «Назад» в браузере сразу уводит с главной.

В адресе ерунда (0, -3, abc) → первые 20, без ошибки. В адресе больше, чем есть людей (45 контактов, а открыто 10 частей) → все 45, кнопки нет.
Новый контакт — первой строкой

После «Добавить контакт» новый человек стоит сверху с подсветкой и меткой «Новый». В двадцатку он не входит, поэтому на первой странице 21 строка. Ниже он не повторяется. Обновили страницу — он всё ещё сверху.

Добавили «Яна Юдина» — по алфавиту она 151-я. Видно: Яна, потом 20 человек с «А», потом кнопка.
Кнопка во время загрузки и с клавиатуры

Пока часть грузится, кнопка не реагирует — двойной клик не пропустит 20 человек. С клавиатуры фокус (рамка, показывающая, какой элемент сейчас выбран) остаётся на кнопке. Когда загрузилась последняя часть и кнопка пропала, фокус переходит на первого из только что показанных людей.

«Пора связаться» не делится

В блоке все, кому пора, сколько бы их ни было. «Показать ещё» есть только у общего списка и на блок не влияет. Человек из блока по-прежнему есть и в общем списке на своём месте — если он дальше первых 20, его видно после «Показать ещё».

4Как проверить руками

Подготовка. Запустите приложение локально (pnpm dev, см. README). Нужно больше 20 контактов: в пустую локальную базу pnpm db:seed добавит 1000 правдоподобных. Если контакты уже есть, команда ничего не делает и ничего не стирает. Для проверок с группой выберите группу, где людей больше 20. Галочки на этой странице только для удобства и не сохраняются. Сейчас фича ещё не сделана: проверять можно после реализации.

5Что агент решил сам

Продуктовые — стоит просмотреть

Вы решили: по 20, кнопка «Показать ещё», только для общего списка, поиск тоже частями, новый контакт первым, число показанных — в адресе. Остальное ниже додумал агент.

  • Нажатия «Показать ещё» не добавляют шагов в историю браузера: «Назад» уводит с главной, а не убирает по 20.
  • Новый контакт не входит в двадцатку: на первой странице 21 строка.
  • После обновления страницы новый контакт остаётся сверху. На место встаёт после поиска, группы или «Все контакты».
  • Новый контакт поднимается наверх только во всём списке без поиска — туда ведёт добавление.
  • Неверное число в адресе — первые 20; больше, чем есть, — все.
  • Пока часть грузится, кнопка бледнеет и не нажимается.
  • С клавиатуры фокус остаётся на кнопке, а после последней части — переходит на первого из новых людей.
  • Из карточки, открытой из результатов поиска, «Все контакты» ведёт к первым 20 всего списка: поиск и сейчас не сохраняется.

Технические — на экраны не влияют

  • Сервер каждый раз отдаёт строки с начала до нужного числа, а не только новые 20. Так адрес — единственный источник правды, и при чужих изменениях между нажатиями ничего не теряется и не повторяется.
  • Чтобы узнать, есть ли ещё, сервер берёт на одну строку больше, чем показывает.
  • Число найденных при поиске считает база отдельным запросом, а не по показанным строкам.
  • Огромное число в адресе ограничено сверху: запрос не падает, а в журнал (лог) не попадают личные данные.
  • Кнопка — готовая кнопка приложения, новых цветов и библиотек нет. База и миграции не меняются, откат на прошлую версию безопасен.
  • Старые автотесты, которые ждали на главной все контакты, переписываются под новое правило, а не удаляются.
