# Design

## Context

Зачем фича — см. `proposal.md`, требования — `specs/keep-in-touch/spec.md`, вид экранов — `mockups/` (раздел «Макеты» в `proposal.md`). Здесь — как это сделать в текущем коде.

Что есть сейчас:

- Таблицы `contacts` и `notes` (`src/db/schema.ts`). У заметки есть только `created_at`; заметки нельзя ни править, ни удалять, поэтому дата последней заметки со временем только растёт. Индекс `notes(contact_id, created_at)` уже есть.
- `addNote` в транзакции обновляет `contacts.updated_at`, но это поле меняется и при правке контакта, поэтому для «последнего общения» оно не годится (спека: правка контакта общением не считается).
- Форма контакта одна на «Новый контакт» и «Изменить» (`contact-form-dialog.tsx`), данные читает `readContactForm` и проверяет `contactSchema` (zod).
- Главная (`src/app/page.tsx`) — серверная страница, читает базу на каждый запрос. Общий список — клиентский компонент `ContactList` со строками `li#contact-<id>`; e2e-тесты считают строки по `li[id^="contact-"]` и сравнивают с числом контактов в базе.
- Всплывающие сообщения — `sonner`, `<Toaster>` смонтирован в `layout.tsx` (`position="bottom-right"`, `closeButton`), поэтому сообщение переживает исчезновение компонента, который его показал. `toast` умеет кнопку действия (`action`).
- В `globals.css` уже подключён `tw-animate-css` — готовые классы появления и исчезновения для Tailwind.
- Прод-образ — `node:24-alpine` без настройки часового пояса, то есть код на сервере живёт в UTC. Postgres знает часовые пояса сам.
- `radix-ui` уже в зависимостях, shadcn-компоненты лежат в `src/components/ui/` (стиль `radix-nova`). Компонента выбора (`select`) пока нет.

## Goals / Non-Goals

**Goals:**

- Одна точка расчёта срока и просрочки — для блока на главной и для карточки, чтобы они никогда не расходились.
- Без новых библиотек и без хранимой «производной» даты последнего общения, которую надо держать в согласии с заметками и отметками.
- Отметка «Связались» и её отмена — короткими серверными действиями, без перезагрузки страницы.
- Существующие e2e-тесты остаются зелёными без правок.

**Non-Goals:**

- Часовой пояс пользователя из браузера и его настройка — сейчас одна фиксированная зона.
- Исправление того, что время заметок на карточке показывается в часовом поясе сервера, — отдельная правка, если понадобится.
- История отметок «Связались»: хранится только последняя.
- Ускорение под десятки тысяч контактов: расчёт рассчитан на личную CRM (сид — 1000 контактов).

## Decisions

### 1. Два новых поля у контакта: частота и отметка «Связались»

- `contact_frequency` — `pgEnum("contact_frequency", ["week", "month", "quarter", "year"])`, колонка необязательная, без значения по умолчанию: `NULL` — «Не задано».
- `contact_marked_at` — `timestamp with time zone`, необязательная, без значения по умолчанию: когда последний раз нажали «Связались». Пишут её только действия кнопки и отмены (решение 8). `updateContact` её не трогает: `readContactForm` это поле не читает, поэтому правка контакта общением не становится.

Имя `contact_marked_at`, а не `last_contacted_at`, — чтобы его не путали с вычисляемым «последним общением» (решение 2): это только одна из двух его составляющих.

Список частот и русские подписи («Раз в неделю»…) живут в одном модуле `src/lib/contact-frequency.ts` без `server-only`: его используют и схема, и форма в браузере, и сервер. `schema.ts` импортирует его относительным путём (`../lib/contact-frequency`): `drizzle-kit` и `scripts/seed.ts` не знают алиаса `@/`.

Альтернативы для частоты:

- `text` с перечнем только в TypeScript — база не защищена от мусора;
- число дней — «месяц» перестаёт быть календарным (спека требует 14 сентября → 14 октября, 31 января → 28 февраля);
- `interval` — гибче, чем нужно: интерфейс даёт только четыре варианта.

Альтернативы для отметки:

- автоматическая заметка «Связались» — отказ (решение пользователя): лента заметок засоряется одинаковыми записями, удалять заметки нельзя, отмена сложнее;
- отдельная таблица отметок — нужна только для истории, а её в требованиях нет.

### 2. Последнее общение не хранится, а вычисляется

```sql
last_contact_at = coalesce(
  greatest((select max(created_at) from notes where contact_id = contacts.id), contacts.contact_marked_at),
  contacts.created_at
)
```

`greatest` в Postgres пропускает `NULL`, поэтому выражение верно, когда нет заметок, нет отметки или нет ни того, ни другого. Подзапрос `max(created_at)` идёт по индексу `notes(contact_id, created_at)`.

Альтернатива — колонка `last_contacted_at` или `next_due_at`, которую обновляют `addNote`, кнопка и `updateContact`. Отказ: это ещё один источник правды, который может разойтись с заметками и отметкой, а выигрыш в скорости на нашем объёме не нужен.

### 3. Срок и просрочка считаются в SQL, по московскому времени

Один модуль `src/lib/keep-in-touch.ts` (`server-only`) строит выражения и отдаёт две функции:

- `listDueContacts()` — контакты, которым пора связаться: `id`, `name`, `contactFrequency`, `overdueDays`; порядок — `overdueDays desc, name asc, id asc`;
- `getKeepInTouchStatus(contactId)` — для карточки: `dueDate` и `today` строками `YYYY-MM-DD` и `overdueDays`, либо `null`, если частота не задана.

Схема расчёта (зона — константа `Europe/Moscow` в этом модуле, `last_contact_at` — из решения 2):

```sql
last_day   = (last_contact_at at time zone 'Europe/Moscow')::date
due_date   = (last_day + case contact_frequency
                          when 'week'    then interval '7 days'
                          when 'month'   then interval '1 month'
                          when 'quarter' then interval '3 months'
                          when 'year'    then interval '1 year' end)::date
today      = (now() at time zone 'Europe/Moscow')::date
overdue    = today - due_date        -- целое число дней; > 0 — «пора связаться»
```

Почему так:

- Postgres сам прибавляет календарные месяцы и прижимает к концу месяца (31 января + 1 месяц = 28 февраля), а часовые пояса знает без настройки контейнера. В JS это пришлось бы писать вручную или тащить библиотеку дат.
- Даты уходят в код строками `YYYY-MM-DD` вместе с `today`, поэтому серверный UTC их не сдвигает. Для карточки строка форматируется через `Intl.DateTimeFormat("ru-RU", { day: "numeric", month: "long", timeZone: "UTC" })`, а год добавляется, только если он отличается от года `today`.

Почему Москва, а не UTC сервера: в UTC сутки начинаются в 03:00 по Москве, и заметка в 01:00 «попадала бы» во вчерашний день. Почему не зона браузера: страница рендерится на сервере, а пользователь один. В Москве нет перехода на летнее время, поэтому «N дней назад» в тестах — ровно N×24 часа.

Альтернатива — считать в JS по дате последней заметки, которую карточка и так загружает. Отказ: для блока всё равно нужен SQL (фильтр и сортировка по всем контактам), и два расчёта легко разойдутся.

### 4. Поле формы — shadcn `Select`

Компонент добавляется командой `pnpm exec shadcn add select` в `src/components/ui/select.tsx`. Он собран на уже установленном `radix-ui` и использует существующие токены (`popover`, `accent`, `input`, `ring`), поэтому новой библиотеки нет. Если сгенерированный код сошлётся на токен, которого нет в `globals.css`, его заменяют на существующий, новые цвета не заводятся.

- Radix `Select` с `name` кладёт значение в `FormData` через скрытый `<select>`, поэтому серверный экшен не меняется по устройству.
- Пустая строка в Radix `Select.Item` запрещена, поэтому «Не задано» — значение `none`; zod превращает `none` и пустое значение в `null`.
- Поле стоит в форме после телефона и почты, на всю ширину, с подписью «Как часто общаться» (макеты `Phone-Form`, `Desktop-Form`). `ContactFormValues` и `EditContactButton` получают `contactFrequency`.

Альтернативы:

- нативный `<select>` — выпадающий список рисует система, и он выбивается из стиля приложения;
- кнопки-сегменты — пять вариантов не помещаются в строку на телефоне.

### 5. Блок «Пора связаться» — клиентский компонент над поиском, данные с сервера

Список считает сервер (`listDueContacts()`), а рисует клиентский `src/components/due-contacts.tsx` (`DueContacts`): строке нужно состояние «подтверждение» с таймером, и блок должен жить, пока последняя строка-подтверждение не исчезла, даже если сервер уже прислал пустой список (решение 8).

- В `page.tsx` `listDueContacts()` вызывается параллельно с остальными запросами, но только когда нет поискового запроса; результат уходит в `<DueContacts items={…}>`. Компонент ничего не рисует, если нет ни строк с сервера, ни строк-подтверждений.
- Место — между заголовком страницы и полем поиска, чтобы блок был первым, что видно.
- Строка — `li` с двумя соседями: ссылка на `/contacts/<id>` (аватар `ContactAvatar`, имя, ниже «Раз в месяц · просрочено на 12 дней» через `pluralize` с формами «день/дня/дней») и галочка «Связались» справа. **Галочка не вложена в ссылку**: кнопка внутри `<a>` — недопустимая разметка, и нажатие ушло бы ещё и в переход. Стрелки «›» в строках блока нет — её место занимает галочка. Заголовок «Пора связаться» — в стиле заголовков страницы (`Highlight`), рядом — число строк в блоке, включая строки-подтверждения.
- На телефоне имя обрезается многоточием, просрочка переносится под частоту — как в макете `Main`.
- **Строки блока не получают `id`**: e2e-тесты ищут строки общего списка по `li[id^="contact-"]` и `#contact-<id>`, а блок не должен ни менять их счёт, ни дублировать `id`.
- Пометка просрочки — существующими токенами (`butter`, как подсветка нового контакта в списке). Новых цветов нет.

### 6. Статус на карточке — ещё одна строка в деталях

В `dl` карточки добавляется `Detail` «Как часто общаться» на всю ширину, после телефона и почты (макеты `Phone-Card-Overdue`, `Phone-Card-Note`, `Desktop-Card`):

- без частоты — стандартное «не указано», кнопки нет;
- с частотой — подпись частоты, строка срока («Следующий раз — до 26 ноября» или «Пора связаться — просрочено на 5 дней» с той же пометкой, что в блоке) и кнопка «Связались».

`getKeepInTouchStatus` грузится в том же `Promise.all`, что контакт и заметки.

### 7. После заметки и отметки обновляется и главная

`addNote` сейчас вызывает `revalidatePath("/contacts/<id>")`. Он переходит на `revalidatePath("/", "layout")` — как `createContact` и `updateContact`. Так же делают действия «Связались» и отмены. Карточка сразу показывает новый срок, главная получает список уже без отмеченного контакта (строку-подтверждение блок держит сам, решение 8), а клиентский кэш роутера не покажет старый блок при возврате кнопкой «Назад». Смена частоты идёт через `updateContact`, там это уже есть.

### 8. «Связались»: действия, галочка в блоке, кнопка на карточке

Серверные действия в `src/app/actions.ts`:

- `markContacted(contactId)` — в транзакции читает прежнее `contact_marked_at`, ставит `now()` и возвращает `{ ok: true, previous: string | null }` (ISO-строка прежнего значения);
- `undoMarkContacted(contactId, previous)` — проверяет, что `previous` — ISO-дата или `null`, и возвращает это значение в `contact_marked_at`.

Обе вызывают `revalidatePath("/", "layout")` (решение 7). Контакт, которого уже нет, — не ошибка, как в `deleteContact`. Отметка сохраняется сразу при нажатии, а не через 5 секунд: если закрыть вкладку в эти секунды, отметка не потеряется.

**Галочка в блоке** — внутри `DueContacts` (решение 5):

- кнопка 44×44 px, вариант `secondary`, иконка `Check` из lucide, `aria-label="Связались: <имя>"`, `title="Связались"`;
- нажатие → `markContacted`; строка переходит в состояние «подтверждение» и запоминается в локальном состоянии блока вместе с `previous` и своим местом в списке. Сервер после `revalidatePath` присылает список уже без этого контакта, а блок держит строку-подтверждение на прежнем месте, пока не кончится её таймер;
- подтверждение (макет `Phone-Home-Marked`): круг с галочкой, «Отметили общение», имя, кнопка «Отменить» на месте галочки, `role="status"`, чтобы диктор прочёл сообщение; внизу строки — тонкая полоска, которая за 5 секунд сжимается до нуля;
- через 5 секунд строка схлопывается по высоте (около 300 мс) и убирается из локального состояния; если строк не осталось, блок исчезает целиком;
- «Отменить» → `undoMarkContacted(contactId, previous)`; таймер останавливается, сервер снова присылает контакт в списке, и на месте подтверждения — обычная строка;
- у каждой строки свой таймер, поэтому несколько отметок подряд не мешают друг другу;
- ошибка любого действия → `toast.error` в стиле остальных форм; при ошибке отметки строка возвращается к обычному виду.

Анимация — CSS-переходами и классами `tw-animate-css`: появление подтверждения — `fade-in`, схлопывание — переход `grid-template-rows` от `1fr` к `0fr`, полоска — переход ширины за 5 секунд. Все переходы выключаются вариантом `motion-reduce:` — при «уменьшить движение» строка меняется и пропадает сразу.

**Кнопка на карточке** — клиентский `src/components/mark-contacted-button.tsx` (`MarkContactedButton({ contactId })`):

- кнопка «Связались» с текстом и галочкой, вариант `secondary`, высота 44 px; на время запроса неактивна (`useTransition`);
- после успеха — `toast.success("Отметили общение", { duration: 5000, action: { label: "Отменить", onClick } })`; обработчик — замыкание на `contactId` и `previous`, вызывает `undoMarkContacted` напрямую, не завися от компонента: сообщение живёт в `<Toaster>` из `layout.tsx`;
- ошибка — `toast.error`.

Альтернативы:

- сохранять отметку только через 5 секунд, а «Отменить» — просто остановка таймера: отказ, отметка теряется, если закрыть вкладку раньше;
- отменять «удалением последней отметки» без прежнего значения: отказ, нельзя вернуть более раннюю отметку (сценарий «Отмена возвращает прежнюю отметку»);
- библиотека анимаций (например, Motion): отказ, хватает CSS и уже подключённого `tw-animate-css`;
- галочка и в блоке, и на карточке: отказ (решение пользователя), на карточке места хватает, а текст понятнее.

### 9. Макеты — холст плюс копия в изменении

Макеты нарисованы на холсте (ссылка в `proposal.md`), их копия лежит в `mockups/`. Файлы `.dc.html` — обычный HTML со стилями прямо в разметке, значения цветов и размеров взяты из `tokens.css`. Они открываются в браузере напрямую: скрипт редактора `support.js` для просмотра не нужен. Ссылки между экранами работают.

При реализации экраны собираются из компонентов и токенов приложения, а макеты служат ориентиром по расположению, текстам и виду. Если макет и требования расходятся, верны требования.

## Risks / Trade-offs

- [Расчёт на каждый показ главной идёт по всем контактам с частотой] → подзапрос `max(created_at)` использует индекс `notes(contact_id, created_at)`; на 1000 контактах сида это миллисекунды. Если станет медленно — тогда уже хранимое поле (решение 2).
- [Зона зашита как Москва] → одна константа в `keep-in-touch.ts`; поменять зону — правка одной строки.
- [Время заметок на карточке показывается во времени сервера (UTC на проде), а сроки — по Москве] → заметка в 01:30 по Москве покажется как «22:30 предыдущего дня», хотя срок считается от правильного дня. Это существующее поведение, вне этой фичи; сказать пользователю.
- [Случайное нажатие «Связались»] → 5 секунд на «Отменить»; после этого — только ждать следующего срока.
- [Отмена вслепую возвращает прежнее значение и может затереть отметку, сделанную в другой вкладке за эти 5 секунд] → пользователь один, принимаем.
- [Сервер уже прислал список без отмеченного контакта, а строка-подтверждение должна продержаться 5 секунд на прежнем месте] → блок хранит строки-подтверждения у себя и вставляет их в список по запомненному месту; это проверяют автотесты сценариев «Подтверждение в строке» и «Последняя строка».
- [Пользователь ушёл с главной раньше 5 секунд] → отметка уже сохранена, отменить её из блока больше нельзя; принимаем.
- [На телефоне галочка в строке блока чуть сужает место под имя] → она всего 44 px; имя обрезается многоточием, просрочка переносится на вторую строку (макет `Main`).
- [Пользователь за раз задаст частоту многим старым контактам без заметок, и блок станет длинным] → это ожидаемо по спеке («с дня добавления контакта»); блок без ограничения, строки компактные, а галочка убирает человека одним нажатием.
- [e2e-тесты работают на локальной базе с живыми данными, в блоке могут быть чужие контакты] → новые тесты проверяют только свои контакты (по суффиксу в имени) и их взаимный порядок, а не весь блок.

## Migration Plan

1. `pnpm db:generate` создаёт `drizzle/0001_*.sql`: `CREATE TYPE "contact_frequency" …` и два `ALTER TABLE "contacts" ADD COLUMN` — `"contact_frequency" "contact_frequency"` и `"contact_marked_at" timestamp with time zone`. Колонки без значения по умолчанию, таблица не переписывается.
2. Выкатка — обычная: миграции разовым контейнером, затем новый образ, smoke `/health`.
3. Ручной откат на прошлый образ безопасен: старый код выбирает колонки по своей схеме и новые не видит. Колонки и тип остаются в базе и при повторной выкатке не мешают.
