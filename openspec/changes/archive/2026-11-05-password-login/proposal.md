# Proposal

## Why

Сейчас войти можно только по ссылке из письма: для каждого входа нужно открывать почту, а если письмо задержалось или почта недоступна, в приложение не попасть. Нужен второй способ — по почте и паролю, с восстановлением и сменой пароля, чтобы человек сам выбирал, как ему удобнее. Вход по ссылке остаётся как есть. Логином служит почта, поэтому появляется и её смена: своей страницы для управления аккаунтом в приложении ещё нет.

## What Changes

- **BREAKING** Страница входа делится на две вкладки: «Вход по ссылке» (первая, открыта сразу) и «Почта и пароль». Браузер запоминает последнюю выбранную вкладку. На вкладке ссылки всё работает как раньше, те же тексты и кнопка
- Вкладка пароля: поля «Почта», «Пароль», кнопка «Войти», «Забыли пароль?» и подсказка «Ещё не зарегистрированы? Войти по ссылке»
- Отдельной регистрации нет: первый вход по ссылке по-прежнему создаёт пользователя. Первый пароль задаётся уже в приложении, в настройках, или через «Забыли пароль?»
- Новая страница «Настройки»: открывается кликом по почте в шапке, отдельной кнопки нет. Два блока: почта и пароль
- Пароль в настройках: задать первый; если пароль уже есть — сменить, указав текущий
- Почта в настройках: сменить, указав текущий пароль. Ссылка на 15 минут уходит на новую почту, почта меняется после перехода по ней, на старую сразу приходит уведомление. Без пароля смена недоступна, настройки предлагают сначала его задать
- «Забыли пароль?»: письмо со ссылкой на 15 минут, одноразовой; новая ссылка гасит старые. После смены пароля все устройства выходят
- Письмо-уведомление «Пароль изменён» после каждой установки и смены пароля
- Требования к паролю: от 8 до 128 символов, любые символы; требований к цифрам и спецсимволам нет
- Защита от подбора: не больше 5 неудачных попыток на почту за 15 минут и общий лимит запросов с одного IP
- Письма для смены пароля и смены почты считаются в общий с письмами входа лимит: 3 письма на почту за 10 минут
- Сообщения не выдают, есть ли такой пользователь и задан ли у него пароль
- Хранение: пароль — только в виде медленного солёного хэша (scrypt с параметрами OWASP), в базе и логах самого пароля нет; ссылка смены пароля в базе — только хэш
- Better Auth остаётся основой, новых библиотек и сервисов нет; своих таблиц для паролей нет: хэш лежит в существующей таблице `accounts`

## Capabilities

### New Capabilities

- `password-login`: вход по почте и паролю, защита от подбора, страница «Настройки» (пароль и почта), «Забыли пароль?», письма о смене пароля и почты, требования к паролю и его хранение

### Modified Capabilities

- `user-login`: «Без входа — страница входа» — две вкладки вместо одной формы; «Не больше 3 писем на почту за 10 минут» — лимит общий для всех писем со ссылками; «Почта в шапке и выход» — почта ведёт в настройки

## Impact

- База: новая таблица `login_password_attempts` (неудачные попытки, хранятся 15 минут). Миграция существующие данные не меняет. Хэши паролей — в существующем поле `accounts.password`
- Код: настройки `emailAndPassword`, `user.changeEmail`, `emailVerification` и хуки в `src/lib/auth.ts`, новый `src/lib/password-hash.ts`, новые шаблоны в `src/lib/mail.ts`, actions в `src/app/login/actions.ts`, страницы `/login` (вкладки), `/login/reset`, `/login/email-changed`, новая страница `/settings`, почта в шапке становится ссылкой
- Компоненты: вкладки shadcn/ui `tabs` поверх уже установленного `radix-ui`
- Библиотеки и сервисы: новых нет
- Настройки и сервер: новых строк в `.env` нет. При активной проверке пароля приложение на короткое время занимает около 128 МБ памяти на каждый расчёт
- Тесты: новые Vitest и один сквозной e2e; существующие e2e почти не меняются, потому что вкладка ссылки открыта сразу
- Откат: прошлая версия приложения работает с новой базой, восстанавливать базу не нужно; вход по паролю на время отката пропадёт, вход по ссылке останется. Уже сменённая почта останется новой

## Решения владельца

- Первый пароль задаётся после входа по ссылке, формы регистрации нет
- Вкладки на странице входа: первая и открытая сразу — «Вход по ссылке», выбор запоминается. Заменяет более раннее решение открывать сразу вкладку пароля
- Названия: вкладка «Вход по ссылке», подсказка «Ещё не зарегистрированы? Войти по ссылке»
- Страница «Настройки» открывается кликом по почте в шапке, кнопки «Пароль» в шапке нет. Заменяет более ранний план страницы «Пароль»
- Смена почты по стандарту рынка: текущий пароль, ссылка на новую почту, уведомление на старую. Без пароля сначала нужно его задать
- Минимальная длина пароля — 8 символов
- Проверки по базе утечек (Have I Been Pwned) нет: без внешних сервисов
- Один новый e2e на весь путь; остальное — Vitest и проверка руками

## Решения, которые агент принял сам

- «Логин» — это почта: отдельного имени пользователя нет
- Браузер продолжает запоминать последнюю вкладку: предвыбранная «Вход по ссылке» действует, пока человек не выбрал другую
- Подбор: 5 неудачных попыток на почту за скользящие 15 минут, дальше «Слишком много попыток. Попробуйте через 15 минут или войдите по ссылке.» Вход по ссылке при этом работает, поэтому чужой подбор не запирает человека снаружи. Удачный вход обнуляет счётчик
- Смена пароля в настройках завершает вход на других устройствах, это устройство остаётся. После «Забыли пароль?» выходят все устройства, включая текущее, и человек входит с новым паролем: сразу войти нельзя
- Текущий пароль при смене пароля и почты обязателен и считается в те же 5 попыток
- **Смена почты не выводит другие устройства:** пароль прежний, а о запросе сообщает письмо
- **Уведомление на старую почту уходит сразу при запросе**, а не после смены: иначе владелец узнает, когда почта уже сменилась. Письмо уходит и если новая почта занята
- **Занятая новая почта не раскрывается:** экран тот же, письмо-ссылка не уходит. Человек увидит только, что письма нет
- Если запросить смену почты дважды, обе ссылки работают 15 минут, но сработает только первая открытая: после неё старой почты в аккаунте уже нет
- Письмо на новую почту считается в лимит этой новой почты
- Новый пароль вводится один раз, без поля «повторите»: вместо него кнопка показать пароль в каждом поле пароля
- Кнопка «Войти по ссылке» в подсказке переключает на вкладку ссылки
- Введённая почта сохраняется при переключении вкладок и переходе в «Забыли пароль?»
- «Забыли пароль?» открывается прямо на странице входа, без отдельного адреса
- Ссылка смены пароля живёт 15 минут, как ссылка входа (у Better Auth по умолчанию час)
- Для неизвестной почты письмо не уходит, экран тот же: «Если для <почта> есть аккаунт, мы отправили на неё ссылку…». В лимит такой запрос тоже считается, иначе лимит выдавал бы, есть ли пользователь
- **Письмо для смены пароля уходит в фоне.** Если почтовый сервис недоступен, человек всё равно увидит «Проверьте почту», а причина попадёт в лог. Иначе по ошибке и по времени ответа можно было бы понять, есть ли такая почта. Письма входа по ссылке работают как раньше. Так же, в фоне, уходят письма смены почты
- В настройках есть «Забыли текущий пароль?»: письмо на свою почту, без выхода из приложения
- Первый пароль задаётся без дополнительной проверки: человек уже вошёл. Защита — письмо-уведомление
- Письма-уведомления в лимит не считаются: их никто не запрашивает, и они не должны пропадать
- Тексты писем и экранов — в спеке `password-login`, по образцу существующих

## Открытые вопросы владельцу

Нет. Память сервера проверена 5 ноября: всего 1,8 ГБ, свободно 1,1 ГБ, подкачка 899 МБ. Параметры хэша остаются как в плане

## Вне объёма

Форма регистрации, отдельный логин вместо почты, двухфакторная проверка, вход через Google и соцсети, проверка пароля по базам утечек, смена почты без пароля или без доступа к новой почте, отмена уже подтверждённой смены почты из приложения, список устройств и выход с выбранных устройств, удаление аккаунта, отказ от пароля после его установки, принудительная смена пароля по сроку.
