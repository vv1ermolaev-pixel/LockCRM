# Spec Delta

## Purpose

Как человек входит в приложение по ссылке из письма и выходит из него. Паролей нет: первый вход по ссылке и есть регистрация. Без входа приложение не открывается.

## ADDED Requirements

### Requirement: Без входа — страница входа

Без входа приложение SHALL показывать страницу входа вместо любой своей страницы. На странице входа — заголовок «Вход в приложение», под ним «Введите почту — пришлём ссылку для входа. Пароль не нужен.», поле «Почта» и кнопка «Получить ссылку для входа». Вошедший пользователь, открывший страницу входа, MUST попадать на главную.

#### Scenario: Открыл главную без входа
- **WHEN** человек без входа открывает адрес приложения
- **THEN** видна страница входа: «Вход в приложение», пояснение про ссылку на почту, поле «Почта» и кнопка «Получить ссылку для входа»; контактов не видно

#### Scenario: Открыл карточку контакта без входа
- **WHEN** человек без входа открывает ссылку на карточку контакта
- **THEN** видна страница входа, данных контакта не видно

#### Scenario: Вошедший открыл страницу входа
- **WHEN** вошедший пользователь открывает адрес страницы входа
- **THEN** открывается главная с его контактами

### Requirement: Запрос ссылки для входа

После ввода почты и нажатия «Получить ссылку для входа» сервер SHALL отправить на эту почту письмо со ссылкой для входа, а форма MUST смениться экраном «Проверьте почту» с текстом «Отправили ссылку для входа на <почта>. Ссылка работает 15 минут.» и кнопкой «Ввести другую почту». Ответ MUST быть одинаковым для новой почты и для почты, под которой уже входили. Первый вход по ссылке создаёт пользователя: отдельной регистрации нет, имя не спрашивается.

#### Scenario: Ссылка отправлена
- **WHEN** человек вводит `anna@example.com` и нажимает «Получить ссылку для входа»
- **THEN** вместо формы — «Проверьте почту» и «Отправили ссылку для входа на anna@example.com. Ссылка работает 15 минут.», в ящике `anna@example.com` — письмо со ссылкой

#### Scenario: Ввести другую почту
- **WHEN** на экране «Проверьте почту» человек нажимает «Ввести другую почту»
- **THEN** снова видна форма, в поле — почта, на которую ушло письмо, её можно исправить и запросить ссылку снова

#### Scenario: Новая и известная почта — один ответ
- **WHEN** человек запрашивает ссылку для почты, под которой никто не входил, а потом для почты, под которой уже входили
- **THEN** оба раза виден один и тот же экран «Проверьте почту», без намёков, есть ли такой пользователь

#### Scenario: Первый вход — это регистрация
- **WHEN** человек впервые открывает ссылку из письма для `boris@example.com`
- **THEN** он внутри приложения, в шапке `boris@example.com`; форм регистрации и вопросов об имени не было

### Requirement: Почта для входа проверяется на сервере

Сервер SHALL убирать пробелы по краям почты и не различать большие и маленькие буквы. Неверный адрес MUST давать ошибку под полем «Проверьте адрес почты», форма остаётся на месте, и письмо MUST NOT уходить. Та же проверка MUST действовать для запроса, пришедшего на сервер не из формы.

#### Scenario: Пробелы и большие буквы
- **WHEN** человек вводит `  Anna@Example.COM ` и нажимает «Получить ссылку для входа»
- **THEN** видно «Отправили ссылку для входа на anna@example.com…», письмо пришло на `anna@example.com`

#### Scenario: Один пользователь при разном написании
- **WHEN** человек вошёл по ссылке, запрошенной для `Anna@Example.com`, добавил контакт, вышел и вошёл по ссылке для `anna@example.com`
- **THEN** он видит тот же контакт: это один и тот же пользователь

#### Scenario: Неверный адрес
- **WHEN** человек вводит `anna@` и нажимает «Получить ссылку для входа»
- **THEN** форма на месте, под полем — «Проверьте адрес почты», письмо не уходит

#### Scenario: Неверный адрес в запросе не из формы
- **WHEN** запрос на отправку ссылки для `not-an-email` приходит на сервер напрямую, минуя форму
- **THEN** сервер отказывает, письмо не уходит

### Requirement: Вход по ссылке из письма

Ссылка из письма SHALL впускать в приложение и открывать главную со своими контактами. Ссылка MUST работать один раз и не дольше 15 минут после отправки. Запрос новой ссылки MUST гасить все прежние ссылки для этой почты.

#### Scenario: Открыл ссылку
- **WHEN** человек открывает ссылку из письма в течение 15 минут
- **THEN** он внутри приложения, видна главная с его контактами, в шапке его почта

#### Scenario: Ссылка второй раз
- **WHEN** человек вошёл по ссылке, вышел и открывает ту же ссылку снова
- **THEN** вход не происходит, видна страница «Ссылка устарела»

#### Scenario: Ссылка старше 15 минут
- **WHEN** человек открывает ссылку через 16 минут после отправки письма
- **THEN** вход не происходит, видна страница «Ссылка устарела»

#### Scenario: Новая ссылка гасит старую
- **WHEN** человек запросил ссылку, потом запросил ещё одну и открывает ссылку из первого письма
- **THEN** вход не происходит, видна страница «Ссылка устарела»; ссылка из второго письма впускает

### Requirement: Страница устаревшей ссылки

Старая, уже использованная или испорченная ссылка SHALL открывать страницу со значком разорванной ссылки, заголовком «Ссылка устарела», текстом «Запросите новую — она придёт на почту.», полем «Почта» и кнопкой «Отправить ссылку повторно». Если в этом браузере за последние 7 дней запрашивали ссылку, в поле MUST быть подставлена эта почта. Кнопка MUST работать как «Получить ссылку для входа»: те же проверка почты, лимит и экран «Проверьте почту».

#### Scenario: Почта подставлена
- **WHEN** человек запросил ссылку для `anna@example.com` и в этом же браузере открыл ссылку из письма через 20 минут
- **THEN** видна страница «Ссылка устарела», в поле — `anna@example.com`

#### Scenario: Отправить повторно в одно нажатие
- **WHEN** на странице «Ссылка устарела» с подставленной почтой человек нажимает «Отправить ссылку повторно»
- **THEN** видно «Проверьте почту» и «Отправили ссылку для входа на anna@example.com…», в ящике новое письмо, по нему получается войти

#### Scenario: Письмо открыли в другом браузере
- **WHEN** человек запросил ссылку на компьютере, а устаревшую ссылку открыл на телефоне
- **THEN** видна страница «Ссылка устарела» с пустым полем «Почта»; после ввода почты кнопка отправляет новую ссылку

#### Scenario: Испорченная ссылка
- **WHEN** человек открывает ссылку из письма, в которой стёрта часть символов
- **THEN** видна страница «Ссылка устарела»

### Requirement: Не больше 3 писем на почту за 10 минут

На одну почту SHALL уходить не больше 3 писем за любые 10 минут — и со страницы входа, и со страницы «Ссылка устарела». На запрос сверх лимита под полем MUST быть «Слишком часто, попробуйте через несколько минут», форма остаётся на месте, и письмо MUST NOT уходить. Это единственный случай, когда при верной почте не появляется «Проверьте почту».

#### Scenario: Четвёртый запрос
- **WHEN** человек трижды получил ссылку на `anna@example.com` и в те же 10 минут запрашивает четвёртую
- **THEN** под полем — «Слишком часто, попробуйте через несколько минут», четвёртого письма в ящике нет

#### Scenario: Лимит у каждой почты свой
- **WHEN** на `anna@example.com` уже ушло 3 письма за 10 минут, и человек запрашивает ссылку для `boris@example.com`
- **THEN** видно «Отправили ссылку для входа на boris@example.com…», письмо пришло

#### Scenario: Через 10 минут снова можно
- **WHEN** с первого из трёх писем на `anna@example.com` прошло больше 10 минут
- **THEN** запрос ссылки снова отправляет письмо

### Requirement: Сбой отправки письма

Если почтовый сервис не принял письмо, форма SHALL остаться на месте, под полем — «Не удалось отправить письмо. Попробуйте ещё раз.», а экран «Проверьте почту» MUST NOT появляться.

#### Scenario: Почтовый сервис недоступен
- **WHEN** почтовый сервис не отвечает, и человек запрашивает ссылку
- **THEN** под полем — «Не удалось отправить письмо. Попробуйте ещё раз.»

### Requirement: Письмо для входа

Письмо SHALL приходить от «Личная CRM» с адреса из настроек, с темой «Вход в Личную CRM». Текст письма MUST быть коротким и идти в таком порядке: «Чтобы войти в Личную CRM, перейдите по ссылке. Ссылка работает 15 минут.», кнопка «Войти» со ссылкой для входа, «Если вы не запрашивали вход — просто проигнорируйте письмо.»

#### Scenario: Содержимое письма
- **WHEN** человек запросил ссылку и открыл письмо
- **THEN** отправитель — «Личная CRM», тема — «Вход в Личную CRM»; в письме по порядку: «Чтобы войти в Личную CRM, перейдите по ссылке. Ссылка работает 15 минут.», кнопка «Войти», «Если вы не запрашивали вход — просто проигнорируйте письмо.»

### Requirement: Куда уходят письма

Куда уходят письма, SHALL решать настройки, а не сборка: одна и та же сборка шлёт письма в почтовую заглушку на компьютере разработчика и в автотестах и настоящие письма на сервере. Автотесты MUST NOT слать настоящие письма. В заглушке можно войти под любым адресом.

#### Scenario: На компьютере разработчика
- **WHEN** владелец запустил приложение у себя и запросил ссылку для `test-a@example.com`
- **THEN** письмо видно на странице почтовой заглушки в браузере, по ссылке из него получается войти

#### Scenario: На сервере
- **WHEN** владелец запросил ссылку на сервере для своей настоящей почты
- **THEN** письмо пришло в его настоящий ящик

### Requirement: Вход держится 30 дней

Вход SHALL держаться 30 дней с последнего захода на этом устройстве: каждый заход продлевает срок. Вход на одном устройстве MUST NOT завершать вход на других: можно быть внутри с нескольких устройств и браузеров одновременно.

#### Scenario: Вернулся через неделю
- **WHEN** пользователь вошёл, закрыл браузер и открыл приложение через 7 дней
- **THEN** он внутри без нового входа

#### Scenario: Не заходил больше 30 дней
- **WHEN** пользователь не открывал приложение на этом устройстве 31 день
- **THEN** видна страница входа

#### Scenario: Два устройства
- **WHEN** пользователь вошёл на компьютере, а потом на телефоне
- **THEN** он внутри на обоих, на обоих одни и те же контакты

### Requirement: Почта в шапке и выход

Вошедший пользователь SHALL видеть в шапке свою почту и кнопку «Выйти». «Выйти» MUST завершать вход только на этом устройстве и открывать страницу входа.

#### Scenario: Шапка
- **WHEN** пользователь вошёл как `anna@example.com`
- **THEN** в шапке на главной и на карточке контакта — `anna@example.com` и кнопка «Выйти»

#### Scenario: Выход
- **WHEN** пользователь нажимает «Выйти»
- **THEN** видна страница входа; «Назад» в браузере не показывает контакты

#### Scenario: Выход только на этом устройстве
- **WHEN** пользователь вошёл в двух браузерах и нажал «Выйти» в первом
- **THEN** в первом — страница входа, во втором после обновления страницы он по-прежнему внутри
